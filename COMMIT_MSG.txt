Proxy keys: thousands of them, imported in one go, checked one by one

A public subscription list is thousands of links long and mostly dead, and the
panel could not take one: it read the whole key list once per pasted line, it
stored a key with three round trips, it refused vmess and trojan, which is half
of what the public lists are made of, and it stopped a carrier at sixty-four
keys.

The import now reads the carrier's room once, parses every line, and writes
the keys in batches of five hundred. The link is keyed by the hash of its
plaintext, so the same link imported twice keeps its row and only gains the
carriers it did not have. The parser reads vmess, whose format is a base64 JSON
object rather than a URL, and trojan, and it takes a shadowsocks link apart by
hand when its credentials make it unreadable as a URL. The carrier limit is
now a candidate pool, not a working set: the panel keeps thousands and the node
materializes the ones that work.

The node checks every key on its own against the services its carrier has to
reach, not the carrier as a whole, so the score of a key says whether that key
reaches the provider. The pool balances over what it knows, and a key that
cannot open a connection goes into a cooldown instead of being tried again and
again.

The panel hands a node a bounded list per carrier, the keys that were seen to
work first, so the node is not asked to open a listener for every link in the
list.
